# Mastering Nmap: The Comprehensive Guide to Network Exploration

Nmap (Network Mapper) is the industry standard for network discovery and security auditing. Whether you are mapping a network, taking inventory, managing service upgrade schedules, or monitoring host or service uptime, understanding the nuances of Nmap's scanning techniques is essential.

This guide covers host discovery, advanced scanning techniques, performance tuning, and firewall evasion, providing scenarios for when to use each method.

---

## 🔍 Host Discovery

Before scanning ports, you must determine which hosts are "alive" (active) on the network. This saves time by avoiding scans on empty IP addresses.

### Key Discovery Options

| **Nmap Option**      | **Description**                                                        |
| -------------------- | ---------------------------------------------------------------------- |
| `10.10.10.0/24`      | Target network range.                                                  |
| `-sn`                | Disables port scanning.                                                |
| `-Pn`                | Disables ICMP Echo Requests                                            |
| `-n`                 | Disables DNS Resolution.                                               |
| `-PE`                | Performs the ping scan by using ICMP Echo Requests against the target. |
| `--packet-trace`     | Shows all packets sent and received.                                   |
| `--reason`           | Displays the reason for a specific result.                             |
| `--disable-arp-ping` | Disables ARP Ping Requests.                                            |
| `--top-ports=<num>`  | Scans the specified top ports that have been defined as most frequent. |
| `-p-`                | Scan all ports.                                                        |
| `-p22-110`           | Scan all ports between 22 and 110.                                     |
| `-p22,25`            | Scans only the specified ports 22 and 25.                              |
| `-F`                 | Scans top 100 ports.                                                   |
| `-sS`                | Performs an TCP SYN-Scan.                                              |
| `-sA`                | Performs an TCP ACK-Scan.                                              |
| `-sU`                | Performs an UDP Scan.                                                  |
| `-sV`                | Scans the discovered services for their versions.                      |
| `-sC`                | Perform a Script Scan with scripts that are categorized as "default".  |
| `--script <script>`  | Performs a Script Scan by using the specified scripts.                 |
| `-O`                 | Performs an OS Detection Scan to determine the OS of the target.       |
| `-A`                 | Performs OS Detection, Service Detection, and traceroute scans.        |
| `-D RND:5`           | Sets the number of random Decoys that will be used to scan the target. |
| `-e`                 | Specifies the network interface that is used for the scan.             |
| `-S 10.10.10.200`    | Specifies the source IP address for the scan.                          |
| `-g`                 | Specifies the source port for the scan.                                |
| `--dns-server <ns>`  | DNS resolution is performed by using a specified name server.          |
| `--stats-every=5s`   | Define a specific time interval to receive progress updates.           |


### Discovery Scenarios

**Scenario 1: Mapping a Whole Network**
To identify all live hosts in the `10.129.2.0/24` range without checking ports:

```
sudo nmap 10.129.2.0/24 -sn -oA tnet | grep for | cut -d" " -f5
```

_This disables port scanning (`-sn`) and saves the output (`-oA`)._

**Scenario 2: Scanning from a List**

If you have a specific list of targets (e.g., `hosts.lst`):

```
sudo nmap -sn -oA tnet -iL hosts.lst
```

_Only active hosts from the file will respond._

**Scenario 3: Troubleshooting "Offline" Hosts**

If a host seems down but you suspect it's alive (firewall blocking ICMP), use `-PE` to force ICMP Echo or `--reason` to see the packet logic:

```
sudo nmap 10.129.2.18 -sn -oA host -PE --reason
```

_Nmap might report it's "alive" because it received an ARP response rather than an ICMP reply._

## ⚔️ Scanning Techniques

Once hosts are discovered, the next step is determining which ports are open.


### 1. TCP SYN Scan (`-sS`)

 **Usage:** `sudo nmap -sS <target>`
    
 **Default:** Yes, for root users.
    
 **Mechanism:** Sends a `SYN` packet. If the target responds with `SYN-ACK`, the port is **open**. Nmap immediately sends `RST` to drop the connection.
    
 **Pros:** Fast and stealthy (does not complete the 3-way handshake).
    
 **Cons:** Requires root privileges; can be blocked by firewalls dropping SYN packets.
    

### 2. TCP Connect Scan (`-sT`)

 **Usage:** `nmap -sT <target>`
    
 **Default:** Yes, for non-root users.
    
 **Mechanism:** Completes the full TCP 3-way handshake (`SYN` -> `SYN-ACK` -> `ACK`).
    
 **Pros:** Most accurate/reliable; works without root privileges.
    
 **Cons:** Slower and noisy. Creates a full connection in the target's logs, making it easily detectable by IDS/Firewalls.
    

### 3. UDP Scan (`-sU`)

 **Usage:** `sudo nmap -sU <target>`
    
 **Mechanism:** Sends UDP packets.
    
     Response: Data/Service reply -> **Open**.
        
     Response: ICMP Port Unreachable -> **Closed**.
        
     No Response: **Open|Filtered**.
        
 **Context:** Crucial for finding services like DNS (53), SNMP (161), or NTP (123).
    
 **Cons:** Extremely slow due to protocol timeouts.
    

**Example: Fast UDP Scan**

To speed up UDP scanning, limit retries and timeout:

```
sudo nmap -sU --top-ports 50 -T4 -Pn --max-retries 2 --host-timeout 30s <target>
```

## 🧩 The Nmap Scripting Engine (NSE)

Nmap's true power lies in its scripts, which can identify vulnerabilities, misconfigurations, and specific service versions.

|**Method**|**Command**|**Description**|
|---|---|---|
|**Default Scripts**|`-sC`|Runs a category of scripts marked as "default" (safe and useful).|
|**Specific Category**|`--script vuln`|Runs all scripts in the "vuln" category to check for known CVEs.|
|**Specific Script**|`--script banner`|Runs only the specified script (e.g., grabbing the service banner).|

**Common Scripts:**

 `banner`: Grabs the service version banner.
    
 `http-enum`: Enumerates web paths (e.g., `/wp-login.php`).
    
 `vuln`: Checks services against known vulnerability databases (CVEs).

## ⚡ Performance Tuning

Optimizing scan speed is critical for large networks.

|**Option**|**Function**|
|---|---|
|`--max-retries <num>`|Limits the number of times Nmap retries a port.|
|`--min-rate <number>`|Forces Nmap to send at least `<number>` packets per second.|
|`--stats-every=5s`|Get a progress status update every 5 seconds.|
|`-T <0-5>`|Timing templates (0=Paranoid, 5=Insane). `-T4` is standard for modern networks.|

## 🛡️ Firewall Evasion & Advanced Techniques

When simple scans are blocked or dropped, use these techniques to bypass filters.

### 1. Decoys (`-D`)

Hide your IP among random "decoy" IPs. The target sees traffic coming from multiple sources, making it hard to pinpoint the attacker.


```
sudo nmap 10.129.2.28 -p 80 -sS -Pn -n -D RND:5
```

_Generates 5 random IP addresses to disguise the packet origin._

### 2. Source Port Spoofing (`-g` or `--source-port`)

Firewalls often whitelist traffic coming _from_ specific ports (like DNS port 53) to allow backward compatibility.



```
sudo nmap 10.129.2.28 -p 50000 -sS -Pn -n --source-port 53
```

_Attempts to bypass the firewall by pretending the traffic originates from a DNS server._

### 3. Source IP Spoofing (`-S`)

If a specific subnet is allowed through the firewall, you can spoof your source IP to match it (requires the ability to capture the response, e.g., on the same local network).



```
sudo nmap 10.129.2.28 -n -Pn -O -S 10.129.2.200 -e tun0
```

## 📂 Output & Reporting

Always save your scans. The `-oA` flag is the industry standard practice.



```
sudo nmap 10.129.2.0/24 -sn -oA tnet
```

**Saves three files:**

1. `tnet.nmap`: Human-readable text.
    
2. `tnet.xml`: XML for importing into other tools (Metasploit, etc).
    
3. `tnet.gnmap`: Grepable format for easy command-line parsing.

## 🛠️ Living Off the Land (Alternative Tools)

Sometimes Nmap is not available (e.g., on a compromised host).

### Netcat (`nc`)

**TCP Scan:**


```
nc -nvv -w 1 -z 192.168.50.152 3388-3390
```

_`-z` indicates "Zero-I/O" (scan mode), `-w 1` is timeout._

**UDP Scan:**



```
nc -nv -u -z -w 1 192.168.50.149 120-123
```

_`-u` specifies UDP mode._

### PowerShell (Windows)

If you are on a restricted Windows host, use this one-liner to scan ports 1-1024:



```
1..1024 | % {echo ((New-Object Net.Sockets.TcpClient).Connect("192.168.50.151", $_)) "TCP port $_ is open"} 2>$null
```

_Alternatively, use `Test-NetConnection -Port 445 <IP>` for single ports._
